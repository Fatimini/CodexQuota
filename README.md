# CodexQuota — Codex 额度菜单栏工具

> **非官方工具，与 OpenAI 无关联。** Codex / ChatGPT 是 OpenAI 的商标；本项目未获 OpenAI 赞助、背书或授权。

原生 macOS 菜单栏 App，近实时显示当前 ChatGPT 账号的 **Codex 剩余额度**：
菜单栏为 SF Symbols `timer` 图标 + `5h：xx%｜周：xx%`（单色模板图标，随系统深浅色自适应），点击展开详情面板；
面板内置**历史曲线**，可看 6 小时 / 24 小时 / 7 天的剩余额度走势。

## 隐私（先看这里）

- **唯一落盘文件**：为绘制走势，App 会把**时间戳 + 窗口时长 + 剩余百分比**写入
  `~/Library/Application Support/CodexQuota/history.json`；**不含**邮箱、账号、额度原始响应或任何凭据。
  默认保留 7 天（超期自动裁剪），可在面板内一键「清除历史」。
- 除该文件外：**所有数据仅存在本机内存**，不外发、不上传、无遥测、无云端服务。
- App **不读取** `~/.codex/auth.json`、浏览器 Cookie、API Key 或任何 Session Token；
  认证完全由本机 Codex CLI 自持。
- 界面中的邮箱一律打码（形如 `ab***@example.com`）。

## 功能

- 菜单栏常驻显示 5 小时窗口与 7 天（周）窗口的剩余百分比，告急（剩余 ≤10%）变红
- 详情面板：进度条、重置倒计时、套餐/账号/连接状态/CLI 版本
- 历史曲线：6 小时 / 24 小时 / 7 天切换，可一键清除本机历史
- 中英文跟随系统语言，切换后界面即时重译（含已存在的错误状态）

## 使用

1. 启动后菜单栏出现 `timer` 图标与剩余百分比（**无 Dock 图标**，只驻留菜单栏）；
2. 点击图标展开详情面板：各窗口剩余进度条、重置倒计时、套餐 / 账号 / 连接状态 / CLI 版本；
3. 面板中部是历史曲线，用分段控件切换 **6 小时 / 24 小时 / 7 天**；
4. 「清除历史」需点两次：按钮先变为红色的「确认清除？」，再点一次才真正清除；
   **点击面板空白处即取消**确认状态；
5. 「立即刷新」手动拉取一次，「退出」结束 App。

## 数据来源与刷新策略（近实时，非秒级）

数据层通过本机 Codex CLI 的 `codex app-server`（stdio JSON-RPC）：

1. App 启动时拉起**一个**长期运行的 App Server 子进程，initialize 握手后立即全量读取；
2. 收到 `account/rateLimits/updated` 通知仅作触发信号，回源 `account/rateLimits/read` 取全量（通知载荷是残缺版，不直接渲染）；
3. 每 3 分钟兜底轮询；
4. Mac 从休眠唤醒时立即刷新（`NSWorkspace.didWakeNotification`）；
5. **每个 JSON-RPC 请求有 10 秒响应超时**：超时后清理该请求、触发 `readFailed`
   （有历史快照则界面转为「已过期」），并终止卡死进程、按退避策略重连；
6. 子进程崩溃后退避重连 1s → 2s → 5s → 30s（之后保持 30s），恢复后立即全量读取。

解析优先级：`rateLimitsByLimitId.codex` → 回退 `rateLimits`。
剩余比例 = `100 − usedPercent`；窗口按 `windowDurationMins` 动态换算，不写死档位。
数值字段有严格校验：`usedPercent` 只接受 0～100 的整数，类型不符或越界一律视为未返回，不截断、不猜测。

## 兼容性

> 本工具依赖 OpenAI 当前公开文档中列出的 `account/rateLimits/read` 与 `account/rateLimits/updated`
> 本地接口。该接口当前无需启用 `experimentalApi` 即可使用；但 Codex App Server 的行为和字段
> 可能随版本变化，软件会在读取失败时明确提示兼容性问题。

## 历史曲线（本地记录）

每次成功读取都会进入历史采样：

| 情形 | 处理 |
| --- | --- |
| 数值未变，且距上次采样 < 60s | 丢弃 |
| 数值未变，且距上次采样 ≥ 60s | 追加（心跳点，保证曲线连续） |
| 数值变化，且距上次采样 < 10s | 就地更新最后一条（不堆积） |
| 数值变化，且距上次采样 ≥ 10s | 追加 |

- 保留期 7 天，另设 20,000 条上限；绘制时先按组保留高低点及首尾，抽稀至多 300 点，减少漏掉短暂低谷和恢复的情况；
- 绘图再去除半个百分点以内的冗余转折，用圆角线段连接，避免整数台阶上的插值鼓包；这个误差上限仅针对抽稀后点列的简化，不是对所有原始记录的误差承诺；原始百分比和历史文件不变；
- 文件损坏时降级为空历史，不影响主功能；
- **只在 App 运行时采样**：退出或休眠期间是空缺的，不补点、不插值。

## 数据边界（不做什么）

- **只显示 Codex 限额**，不是 ChatGPT 网页对话/图片/文件上传额度（不同的桶）；
- 窗口缺失、读取失败时显示「暂未返回」或保留上次数据标「已过期」，**不显示 0%、不编造数值**；
- 无额度重置按钮、无桌面挂件、无浏览器扩展、无云端服务；
- 不承诺秒级实时：额度快照粒度为「通知 + 3 分钟轮询」；
- 历史是本机展示数据，不是对账凭证。

## 多语言

界面语言跟随系统首选语言：**中文（简/繁）显示中文，其他语言显示英文**，切换后即时生效。
文案集中在 `Sources/CodexQuota/L10n.swift`，新增语言只需扩展该文件。

> 设计要点：状态层只保存**结构化错误**（`QuotaFailure` 枚举：类型＋参数），不保存译文；
> 错误在渲染时才翻译，因此语言切换后已有错误状态也能完整重译，不会中英混排。

## 版本与发布

版本号由根目录 `VERSION` 文件**唯一**决定，升版本请先改它：

```bash
git clone https://github.com/Fatimini/CodexQuota.git
cd CodexQuota

./build_app.sh "本次改动摘要"    # 编译 → 打包 → ad-hoc 签名 → 签名校验 → 版本一致性校验
open CodexQuota.app              # 启动（LSUIElement，无 Dock 图标，只驻留菜单栏）
```

- `build_app.sh` **不接受命令行版本参数**，避免产物版本与仓库版本分叉；
- 本仓库**不含任何预编译产物**（`.app`、构建缓存、本机归档均在 `.gitignore` 中）；
- 正式发布走 **Git tag + GitHub Release**；版本轨迹见 `CHANGELOG.md`。

## 已知限制

- `codex app-server` 整体被官方标注为 experimental、不支持生产负载，CLI 升级可能导致协议变化；
  App 已做全字段可选解析 + 严格数值校验，解析失败时降级为「已过期/暂未返回」；
- 未登录（`account: null`）状态有单测覆盖，但依赖真实登录态的场景需使用者自行验证；
- 休眠唤醒刷新、真机断网后的菜单栏渲染：**逻辑有测试覆盖，但尚未做真机人工目验**；
- 历史曲线只在本机累积，不做云端同步；
- 当前产物仅 arm64，且为 ad-hoc 签名（未公证）；
- 额度读取依赖本机到 ChatGPT 后端的连通性：后端不可达时会**明确显示失败原因**；
  若已有上次成功数据，则保留并标注「已过期」，不会拿旧数据冒充最新。
